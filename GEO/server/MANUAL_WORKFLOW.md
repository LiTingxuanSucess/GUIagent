## 六平台采样配置（2026-10-22）

本机当前启用 `GEO_WORKFLOW_SITE_ISOLATION=1`、`GEO_QUEUE_WORKERS=6`、
`GEO_SITE_CONCURRENCY=6`。Excel 批次控制器使用 `--concurrency 6 --site-isolation`：
六个平台各一路，相同平台同一时间只跑一个样本。账号资料仍按手机号隔离；
各平台使用独立标签页和站点租约。人工待办只占用对应平台，其他平台继续执行。
普通后台登录、删除账号、停用账号等操作仍受整个账号的保护。

2026-10-23 起，本机采样控制器启用 `--round-policy per_site`：每个平台自己的
100 题完成后立即进入下一遍，依次连续执行第 1、2、3、4、5 遍，无需等待其他
平台。例如 DeepSeek 第一遍完成 100 题后，立即从第二遍 Q201 开始。
正文、搜索来源和已验证分享链接齐全才计为合格；本平台待人工或缺项只阻塞本平台，
不阻塞其他平台。启动参数和批次记录均保存此配置，重启后继续沿用。
页面与飞书定时报表按平台显示当前轮次；未配置时仍默认使用 `global` 同步规则。
连续澄清答复会单列为 `needs_clarification`，停止相同问题的盲目重试，保留正文、
分享链接和缺少搜索来源的真实记录，不计入合格数。只有显式启用
`--allow-clarification-advance`，这类记录才作为已处理异常参与轮次推进。

只缺分享验证的样本进入 `share_pending`，保留原任务、正文和来源，不重新提问。
控制器读取原尝试私有缓存中已经观测到的分享链接，在独立匿名浏览器中复核对应
原答案，最多三次并退避；缺少候选链接或复核耗尽时保留缺项等待处理，不计为完成。
验证证据单独保存，原尝试结果不覆盖。旧批次中仅缺分享的重试或耗尽记录会在恢复
控制器时转入此流程，正在执行和待人工的任务保持原归属。
补验支持原缓存的相对路径，区分浏览器启动与验证超时，验证成功后先写入证据再
清理匿名浏览器。修复前因补验进程失败耗尽的记录，可保留旧历史再进行一次有界补验。

原问题不匹配与提交结果未确认会保留具体错误，不再显示成通用平台请求失败。
待办中的“恢复原对话并采集”只导航到记录绑定的持久对话地址，重新核对原问题、
轮次和登录状态；地址丢失、本地临时地址或轮次不符时继续保留待办，不自动换轮。
“采集当前已提交的本题”是独立的人工确认操作：只接受原账号标签页内、文本与
本题一致且只有一次提问的持久对话；旧绑定另存历史，再续读当前回答，不发送问题。
其他问题或多轮重复提问无法通过该操作替换原记录。

启用 `GEO_MANUAL_AUTO_RECOVERY=1` 后，发送待确认、登录/验证、生成超时和页面
就绪待确认会先自动复核，按60秒、180秒、540秒退避，同一状态最多三次。
自动复核只续读原提问；当前唯一提问与任务一致、登录和页面状态均正常时，可留档
旧绑定并读取已生成的回答。明确的其他问题、多轮重复、额度限制、标签页丢失和
人工接管不会被自动改绑或重复提问。页面会区分“等待自动复核”和人工待办。
豆包中中文与数字/英文边界的显示空格不再造成问题误判，英文内部空格仍严格比较。

管理员可 `POST /api/admin/cursor-health` 发起一次只读模型可用性复查；真实模型
返回才会清除账单/认证故障状态，`GET` 保持只读。明确提供的千问分享可通过人工
任务操作 `share`、`share_url`、`revision` 补采：匿名核对单轮原题、正文和实际
搜索来源后完成原任务，成功后继续下一题，不重新提问。

`/admin/manual` 顶部同步展示当前批次总进度、本轮进度、五轮分别完成数、六个平台
的本轮及累计完成数，以及带题号的卡点和缺项。每三秒刷新一次；可从卡点直接跳到
对应人工待办。超过两分钟没有采样心跳时标记进度待更新，读取失败保留上次显示。
进度接口沿用管理员权限，不返回飞书 Webhook、私有文件路径和采样原始记录。

`GEO_SHARE_UI_LOCK_FILE` 对复制分享链接和前台分享操作加进程锁，避免系统剪贴板
在多平台之间串用；回答生成及匿名分享验证仍并发执行。

`GEO_MANUAL_AUTO_RECOVERY=1` 时，Kimi“聊天的人太多了”和豆包“算力紧张”
会刷新重试。仅在明确的平台拒绝证据下重新提问；原回答已生成时继续采集，
问题归属或发送状态不明时暂停，不盲目重复提交。持续繁忙按
`GEO_BUSY_RETRY_SEC=60` 冷却重试。

遇到验证时调用本机 Cursor CLI，随后由服务端独立复核指定标签页并续采原问题。
通过 `GEO_SAMPLING_NOTIFY_CONFIG` 指向私有飞书配置，发现验证和辅助结果都即时

## 操作流程

1. 输入问题、选择平台，提交网页任务。每个手机号使用独立 Chrome 资料，
   同一账号的浏览器由一个任务占用，其他账号可以继续执行。
2. 代码通过本机 CDP 在真实 Chrome 中提问并采集。遇到登录、风控、发送状态不明、
   生成或提取异常，保存原账号、问题、标签页与发送阶段，进入人工待办。
3. 点击“人工接管”和“在 Mac 打开原页面”，在这台 Mac 的 Chrome 内处理。
   远程操作需通过已有远程桌面进入该 Mac。
   打开按钮使用该账号的独立浏览器连接，控制空白页关闭后仍可定位原标签页，
   并恢复最小化窗口、将对应 Chrome 进程切到前台。原页丢失时，仅在私有记录与
   本题、账号、原标签页完全匹配且保存了持久对话链接时重开该链接，并保存新的
   标签页绑定与恢复历史；不排队执行或重新发送问题。本地临时链接无法恢复时，
   在对应任务按钮旁显示具体原因。打开页面不受过期的界面版本号影响，执行操作
   仍严格校验版本号。
   原页关闭且没有可恢复链接时，可点击“新建平台标签页”。它只在原账号的 Chrome
   新开平台首页，保存旧标签页、旧对话及发送状态的历史，并进入人工处理状态。
   已提交或发送待确认的问题，从历史记录找回本题后点击“采集当前已提交的本题”；
   尚未发送的问题，登录完成后点击“已完成验证，继续执行”。新建按钮不会提交
   问题；新标签页有其他问题时不会被当作空白页继续发送。
   新标签页已显示本题时，“已完成验证，继续执行”也会确认当前明确匹配的提问并
   直接续读回答，无需再换一个按钮。文心多轮页面只有最新问题与本题完全一致、
   最新问答成对且回答的完成控件可核实时，才绑定最新轮次；不会拿上一轮回答充数。
   Mac 采集租约通过独立浏览器连接核对原账号的精确标签页 ID，Python 自己连接
   该页读取；后台控制空白页或旧的 Go 页面连接失效不再导致“原标签页不存在”。
   实际标签页丢失与连接暂不可用分别记录，连接问题进入退避复核。
   元宝同时识别当前 `data-conv-outputting=false` 与本条回答的复制工具栏，继续
   生成、停止按钮或缺少完成控件时仍不算结束。千问已经通过原题、完成区域、
   原生来源及稳定性核验的列表式正文，不再套用侧栏短标题启发式丢弃；先保存完整
   回答检查点，分享失败时仍交付正文，采样控制器再单独处理来源/分享缺项。
4. 如果只完成了验证，点击“已完成验证，继续执行”。如果手动发送了问题，点击
   “已手动提交，开始采集”。后端复核当前对话和问题轮次，随后继续读取对应回答。
5. 结果在最近任务中展示，最新结果自动展开；原有查询和结果回调仍可使用。

问题已提交时，代码恢复后继续等待或提取已有回答。提交结果不确定时，会先核对
当前页面；缺少证据时保留待办。重复问题文本还需结合新消息编号或消息位置判断，
切换网址本身不能证明新的问题已提交。

## 占用与恢复

人工待办会保留整个账号浏览器的操作权，阻止其他任务、后台重登和普通后台页面
写操作进入同一浏览器。等待期间不占用任务 worker 或网页执行名额。取消任务或
成功取得回答后，账号占用释放。取消不会删除 Chrome 中已经提交的问题或回答。

每个平台的状态保存于该任务的 `manual_states`；原问题的详细发送记录沿用私有
`data/web-recovery/<job>/<site>/<account>.json`。服务启动时先恢复账号占用，
再启用后台登录流程。执行中或准备恢复的任务在服务重启后回到人工确认阶段，
不会自动重放可能已发送的问题。

Chrome 和原标签页保留时可以继续接管。原标签页已关闭、对话发生变化或问题
无法核实时，任务仍停留人工待办，不自动改绑其他标签页。当前版本需要人工恢复
原页面；无法恢复时可取消原任务后另建任务，并核对平台是否已有回答。

人工等待默认 30 分钟，超过时间显示提示，继续保留页面和账号占用，直到人工
继续或取消；不会因超时静默释放给其他任务。一次自动执行/续读默认最多 180 秒。

新模式的任务固定使用本机网页及人工处理，不自动切换云浏览器、Cursor CLI 或
官方 API；已有任务按原有模式继续执行。历史任务记录不自动迁移为人工任务。

## 配置

当前 Mac LaunchAgent 环境变量：

```text
GEO_CHROME_MODE=mac-cdp
GEO_MANUAL_WORKFLOW=1
GEO_QUEUE_WORKERS=2
GEO_SITE_CONCURRENCY=2
GEO_MANUAL_WAIT_MIN=30
GEO_MANUAL_ROUND_SEC=180
```

`GEO_MANUAL_WORKFLOW` 在接受新请求时保存到任务中，调整开关只影响之后的新请求。
单个任务仍需等待人工处理的账号可以通过取消任务释放。

## 管理接口

全部人工管理接口要求管理员会话，普通用户/AK-SK 无权接管页面。

- `GET /api/admin/manual-tasks`：当前人工工作流是否启用、未完成的平台任务、最近 30 条工作流。
- `POST /api/admin/manual-tasks/{job}/{site}`：`{"action":"claim|open|continue|submitted","revision":N}`。
  版本不匹配、任务已在运行或不在可操作状态时返回 409。
- `POST /api/v1/jobs/{job}/cancel`：取消整个任务，保留已取得的结果。

人工继续操作先保存状态，保存失败不会安排执行；重复或过期操作不会再次进入
执行队列。非管理员任务查询保留 `waiting_manual` 状态，但不包含浏览器、账号、
私有对话地址和人工状态详情。
