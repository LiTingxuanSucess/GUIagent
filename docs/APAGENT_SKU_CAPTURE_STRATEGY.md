# APAgent SKU Capture Strategy

This document records the lessons from the first Apple SKU capture attempts and the intended capture design going forward.

## Lessons Learned

1. Price records are not executable SKUs.
   `sku_price_records` is an observation table. The order flow uses `skus`, so a record must pass QA and promotion before it is considered executable.

2. Historical runs must not be consumed directly.
   `APAGENT_ALL_SKU_PRICE_RECORDS.csv` contains every run, including failed rows, duplicate rows, and superseded strategies. Use the canonical export generated by `APAgent/scripts/sku_price_qa.py`.

3. Product identity must come from the catalog root, not only from dimensions.
   A dimension such as `6_3inch` describes a screen size, not the product model. For iPhone, the catalog product name must remain the model, and screen size belongs in `display` or URL path metadata.

4. Apple option matrices are stateful.
   Mac, iPad, and Watch options are not independent. A valid chip can constrain memory, storage, finish, case size, band, and connection choices. Blind Cartesian products create many fake failures.

5. `part_number` and `selection_path` are the promotion boundary.
   Fixed products can usually be promoted by `part_number`. Configurable products need either a recovered `part_number` after configuration or a reliable `selection_path` that can be replayed during ordering.

6. Failed option edges are not failed SKUs.
   If an option disappears after a prior selection, record it as an unavailable edge in QA/debug metadata. Do not insert it as a SKU candidate.

7. Replay order must use the discovered path order.
   iPad Pro exposes `dimensionFinish` only after capacity is selected. Sorting all dimensions globally caused replay to click glass before capacity, producing false `option not found` errors. Replaying the exact DFS path fixes this class of conditional-option failures.

8. Some configurable roots have no configurable dimensions.
   AirPods Pro 3 and Vision can still be valid product records even without `selection_path`. For these pages, use the product URL leaf as `model_path`/`path` instead of the URL parent segment.

9. Mac identity needs chip and memory in the semantic path.
   The current price table has no separate `processor` or `memory` columns. To avoid collapsing different Mac configurations, Mac `model_path` must include normalized chip and memory tokens, while `storage` remains the SSD capacity.

10. Watch identity needs the product root in the path.
    Case size alone is not unique across Apple Watch SE, Series, Hermès, and Ultra roots. Watch paths must include the catalog product slug plus size/color/connection.

## Target Pipeline

The intended pipeline has five phases:

1. Discover catalog entry points.
   Run `discover_apple_product_catalog.py` to refresh Apple product roots and fixed product pages.

2. Capture fixed products by product page.
   Fixed product pages should be handled first because they are cheap, high coverage, and usually include `part_number`.

3. Capture configurable products with stateful DFS.
   Open the product root, select one dimension, wait for the page to settle, then read the next currently enabled option set. Continue until the page exposes a price and Add to Bag state.

4. QA and canonicalize.
   Generate the canonical candidate set and report:

   ```powershell
   cd C:\workspace\GUIAgent
   py -3.11 APAgent\scripts\sku_price_qa.py
   ```

5. Promote reviewed candidates.
   Promote only records whose promotion state is `direct_part_number` or `selection_path_required`, and verify Add to Bag for each product family before broad import.

## Efficient Capture Order

Use this order when refreshing data:

1. Fixed products:

   ```powershell
   py -3.11 APAgent\scripts\capture_apple_catalog_sku_prices.py --kind fixed_product --concurrency 4 --batch-size 25 --skip-existing-ok
   ```

   Use `--skip-existing-ok` for routine refreshes so the run only captures fixed products that do not already have a successful price record. The current catalog has successful fixed-product coverage, so this should normally be an empty run unless discovery finds new products.

2. iPhone URL-path products:

   ```powershell
   py -3.11 APAgent\scripts\capture_apple_catalog_sku_prices.py --kind configurable --family iPhone --concurrency 1 --batch-size 1 --max-combos-per-product 1000 --product-timeout-seconds 1800
   ```

3. iPad representative roots:

   ```powershell
   py -3.11 APAgent\scripts\capture_apple_catalog_sku_prices.py --kind configurable --family iPad --concurrency 1 --batch-size 1 --max-combos-per-product 500 --skip-existing-sku-ok
   ```

   If a cached graph is stale, rerun one root with `--no-option-cache`. The iPad Pro full matrix is 48 clean records:

   ```powershell
   py -3.11 APAgent\scripts\capture_apple_catalog_sku_prices.py --kind configurable --family iPad --path-contains ipad-pro --concurrency 1 --batch-size 1 --max-combos-per-product 48 --product-timeout-seconds 7200 --skip-existing-sku-ok --no-option-cache
   ```

4. Mac and Watch by one root at a time:

   ```powershell
   py -3.11 APAgent\scripts\capture_apple_catalog_sku_prices.py --kind configurable --family Mac --path-contains macbook-pro --concurrency 1 --batch-size 1 --max-combos-per-product 500
   py -3.11 APAgent\scripts\capture_apple_catalog_sku_prices.py --kind configurable --family "Apple Watch" --concurrency 1 --batch-size 1 --max-combos-per-product 500
   ```

Run QA after each phase. Do not start the next family if the current phase introduces bad model names, high duplicate counts, or missing selection paths.

## Long Run Safety

The capture script writes records after each batch. Use small batches for stateful configurable products and larger batches for fixed products:

- Fixed product pages: `--batch-size 25`, `--concurrency 4`.
- Configurable product roots: `--batch-size 1`, `--concurrency 1`, and an explicit `--product-timeout-seconds`.
- Smoke tests: combine `--limit 5` or `--limit 20` with a small `--max-combos-per-product`.

If a run is interrupted, inspect `sku_price_runs`. A `running` run with no active Python process should be marked `aborted` manually before starting a replacement run.

Observed iPhone timings on 2026-05-27:

- `iPhone 17`: 30 combinations, 30 OK, about 9 minutes.
- `iPhone 17e`: 30 combinations, 30 OK, about 9 minutes.
- `iPhone Air`: 15 combinations, 15 OK, about 5 minutes. A 100-combination attempt exceeded 15 minutes before first batch completion, so expand this root in smaller slices.

Observed iPad timings on 2026-05-27:

- `iPad Pro`: 48 clean combinations. Expanding in slices of 4, 12, 24, then 48 avoided losing progress to transient Apple page failures.
- `iPad Air`: 64 clean combinations.
- `iPad` and `iPad mini`: 24 clean combinations each.

Observed Mac/Watch timings on 2026-05-27:

- `Mac mini`: 13 new combinations, 13 OK. Clean matrix now includes chip, memory, and storage in `path`.
- `Mac Studio`: 20 new combinations, 20 OK. Clean matrix now includes chip, memory, and storage in `path`.
- `MacBook Pro`: 24 new base combinations, 24 OK. The current radio-based DFS reaches screen/glass/chip/color base configs; deeper memory/storage expansion may need additional page-control support.
- `Apple Watch SE 3`: 8 new combinations, 8 OK. Watch paths now include product root, case size, color, and connection.

## Option And Path Cache

Configurable capture stores page exploration state in `sku_capture_cache`:

- `prefix_options`: options discovered after a prefix of selections, used to avoid reopening the page for already explored prefixes.
- `selection_path`: complete configurable SKU paths that have been enumerated.
- `observed_options`: aggregate known option values for a product root.

Routine configurable expansion should use both cache and successful-SKU skipping:

```powershell
py -3.11 APAgent\scripts\capture_apple_catalog_sku_prices.py --kind configurable --family iPhone --path-contains iphone-air --concurrency 1 --batch-size 1 --max-combos-per-product 20 --product-timeout-seconds 600 --skip-existing-sku-ok
```

Use `--no-option-cache` only when Apple changes the page structure or the cached option graph looks stale.

## Completeness Definition

A SKU family is considered complete only when all of these are true:

- Discovery includes the expected product roots.
- Capture has no bad model normalization.
- The latest successful records have stable price, URL, strategy, and selection metadata.
- Duplicate semantic keys are resolved by canonical export.
- At least one representative SKU has passed Add to Bag verification.
- Promotion to `skus` is possible through `part_number` or replayable `selection_path`.

## Current Known Gaps

- Existing historical iPhone records from run 12 include bad size-only model names and should not be promoted.
- Latest configurable records do not include `part_number`.
- MacBook Pro deeper memory/storage expansion likely needs support beyond the currently visible radio graph.
- Apple Watch band pairing is not yet represented; current Watch coverage is case/color/size/connection oriented.
- The UI does not yet expose a review-and-promote workflow from price records into executable SKUs.
