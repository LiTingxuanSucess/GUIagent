## 本次调试发现的问题与最佳实践

### 问题 1：`⊕添加` OCR 误读为 `④添加`

OCR 将圆圈加号特殊字符识别为汉字"④"。

**最佳实践**：picker 使用分级优先策略，不做精确匹配：精确命中词优先级 0，宽松变体（`endswith("添加") and len<=4`）优先级 2，同时维护黑名单（`已添加`/`添加客户`/`添加成员`）。

### 问题 2：`手机号/邮箱` 搜索图标与文字被 OCR 合并

OCR 输出 `Q手机号/邮箱`，搜索图标被识别为字母 Q 并粘连。

**最佳实践**：关键词用子串匹配（`"手机" in text`），不做全文精确比对。OCR 对图标/emoji 的误读几乎是必然的，设计 picker 时默认预留此类容错空间。

### 问题 3：弹窗是独立顶层窗口，`_find_cef_hwnd_at(main_hwnd)` 失效

`添加客户` 和 `发送添加邀请` 都是独立 CEF 弹窗，不在主窗口子树中。用 `main_hwnd` 枚举子窗口找不到弹窗的 `Chrome_RenderWidgetHostHWND`，导致 `WM_CHAR` 发给了主窗口 CEF，字符根本没进弹窗输入框。

**最佳实践**：输入前用 `GetForegroundWindow()` 取当前前台窗口（弹窗打开后就是弹窗本身），再在**前台窗口**的子树里找 CEF。新封装 `type_text_foreground(x, y, text)` 实现此逻辑，对所有弹窗通用。

### 问题 4：`config.yaml` 静默覆盖代码默认值

修改了 `AddCustomerOcrOptions.region_dialog_search` 默认值后，实际运行仍用旧区域，排查了很久才发现是 `config.yaml` 里有 `ocr_region_dialog_search: [0.22, 0.08, 0.88, 0.62]` 覆盖了新值。

**最佳实践**：
- 区域参数改动时必须同步检查 `config.yaml`
- 或在启动时打印"实际生效参数"一行，便于快速核对

### 问题 5：自定义邀请语误点背景，关闭了弹窗

`_pick_invite_input` 用"添加"为关键词，命中了背景联系人面板的"添加时间"字段，点击该位置关闭了 `发送添加邀请` 弹窗。

**最佳实践**：弹窗内操作的目标坐标，应从检测弹窗存在的**同一批 OCR 框**中推算，而不是再次独立 snap → 可能拿到弹窗关闭后的背景页。`_wait_state` 返回值（boxes, iw, ih）即可作为坐标来源。

### 问题 6：诊断文件按名称排序读到旧文件

`read_diag.py` 按文件名字母序取 `all_jsonl[-1]`，`wait_state_*` 排在 `snap_pick_*` 后面，不是最新文件。

**最佳实践**：诊断读取一律用 `max(..., key=lambda f: f.stat().st_mtime)`。

## 遗留问题

`发送添加邀请` 弹窗的输入框修改逻辑尚不稳定，暂不传 `--invite-message` 则使用企微默认邀请语。

**待完成的正确策略：**

2. 在标题正下方约 8% 窗口高度处点击（确保命中弹窗输入框而非背景）
3. 用 `GetForegroundWindow()` + `_find_cef_hwnd_at` 找弹窗 CEF，发 Ctrl+A + WM_CHAR 覆盖默认文案
4. OCR 验证：旧文案消失，新文案出现

## 核心原则

1. 只在人工已把企业微信主窗口放到前台时运行；脚本不主动启动、置顶或唤起窗口。
2. 当前窗口必须是已登录后的 `WeWorkWindow`；如果是 `WeChatLogin`、登录页、安全验证页，停止。
3. 点击目标必须来自当前截图的 OCR/视觉识别结果，再映射到当前窗口坐标。
4. OCR 未命中关键状态时停止并保存截图，不要盲目比例回退。
5. 弹窗内的输入操作，坐标来源必须是**确认弹窗存在时的那批 OCR 框**，避免弹窗关闭后误点背景。

## 禁止事项

- 不要把 `shots/add_customer` 的像素坐标写进生产逻辑。
- 不要把左侧搜索框旁的小 `+` 当成"添加客户"入口。
- 不要把左侧 `+ 添加成员...` 当成"添加客户"入口。
- 不要把背景列表里的 `已添加` 当成搜索结果按钮。
- 不要把弹窗标题 `发送添加邀请` 当成最终"发送"按钮。
- 不要在弹窗操作时再次独立截图定位，用 `_wait_state` 返回的 boxes 直接推算坐标。

## 自适应定位策略

每一步都按以下顺序处理：

1. 截取当前 `WeWorkWindow` 客户区。
2. 通过 OCR 获取文字框和中心点，坐标保留在截图坐标系。
3. 用关键词、相对区域、邻近上下文筛选目标。
4. 将截图坐标按当前客户区宽高映射为屏幕坐标。
5. 点击后再次 OCR 验证页面状态是否进入下一步。

区域约束只能使用归一化比例，例如 `x=0.85~0.99`，不能使用固定像素。
